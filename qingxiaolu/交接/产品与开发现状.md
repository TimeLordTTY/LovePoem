# 情晓录：产品设计与开发现状

核对日期：2026-09-29。这里的“已有代码”只说明源码中能找到实现，不等于已在真机和线上验证可用。

## 产品定位

情晓录是私人写作与资料管理工具，支持电脑网页和 Android App。小说只是项目类型之一，也支持随笔、日记、诗歌、摘录及自定义类别。用户可写短灵感与长文、给项目设封面与标签、管理人物、世界观、章节大纲、情节和故事内时间轴，并按日期浏览全部创作内容。博客式历史页应能直接浏览短内容和图片，长内容展开阅读，按原发布时间排序；右侧日期栏用于跳转。创作历史与小说故事时间轴是两种不同的数据。

用户明确要求：稿件是否同步服务器由每篇或批量勾选决定；私密和待编辑内容不得上传 LovePoem 网站；本地删除不得连带删除云端；历史导入先预览、勾选和编辑，再正式导入。网页和手机都可编辑、管理资料、导入导出；Android 还需要手机权限辅助。电脑本地文件夹同步由用户手动选择“本地→App”或“App→本地”，不是后台自动改写。

## 数据与接口

- 情晓录本地稿件、版本、回收站、网站草稿 ID 映射等主要存在浏览器/Android WebView 的 `localStorage`。`mobile/sync.ts` 可查看键名和同步规则。换电脑不会自动带走未同步的本地草稿；迁机前必须在旧设备逐项确认同步或另行导出。
- 情晓录同步 API：`https://poem.timelordtty.cn/qingxiaolu-api`。源码提供 `/health`、`/v1/auth/login`、`/v1/sync/pull`、`/v1/sync/push`。服务器服务运行于 `127.0.0.1:8082`，使用 MySQL `poem` 库中的 `qx_*` 表。与网站文章 API 是两套接口。
- LovePoem 网站 API：`https://poem.timelordtty.cn/api`。目前上传流程是登录、取得文章类型与系列、上传图片、创建或更新 `PRIVATE + DRAFT` 网站草稿；上传后用户在 LovePoem 后台继续操作。相关字段以 `mobile/WebsitePublish.tsx` 和 LovePoem 控制器为准。
- ChatGPT 扩展是用户点击时读取当前页面已加载文字，确认后写入情晓录；不是 ChatGPT 项目官方双向同步。图片、附件、未滚动加载的旧消息和项目记忆不在其采集范围。
- 历史导入的设计是一次性采集→临时预览→用户确认。QQ 空间导入的原发布时间与图片很重要；不要给说说自造标题。

- 逐条/批量勾选同步、服务器拉取、网站草稿上传、本地删除与回收站。

## 已知问题与下一步优先级

1. **第三方转发仍未通过真机验收。** 用户 2026-08-05 实测：微博可用；微信朋友圈能带图但正文缺失且不稳定；QQ 无障碍导航未动作；一言未能打开。1.6 APK 的无障碍防崩溃和微信填字只是代码修补，未取得用户复测结果。不要称其为已完成。
2. Android 无障碍服务 `HistoryCaptureService` 同时负责历史采集和 QQ/微信辅助，需在真机上验证节点、状态、超时和异常。其旧版本曾出现空指针闪退。
3. 网站构建与源码存在时间差：线上网页构建时间为 2026-08-04，本地 `mobile/` 后续有修改。上线前先比较、备份并回归测试，不能盲目覆盖。
4. 情晓录主目录的 Git 工作树尚未形成可移植的正式提交；需要建立可靠的私有源码仓库或审查后提交。QQ 图片属于私人资料，不能随手推到公共仓库。
5. 本地数据存在浏览器存储里。跨设备迁移、私密内容备份、服务器/本地冲突处理和图片持久化需要系统性验证。
6. 旧网页原型 `app/page.tsx` 有展示性按钮与假数据，不能作为真实功能验收。实际产品入口为 `mobile/`。

## 验收原则

对每个按钮都做真机或浏览器端到端验证：输入内容→保存/预览→退出重进→刷新/同步→对端检查。第三方平台只在用户确认发布前填入内容，不得自动发表。失败时明确显示失败，不显示“已同步”或“已建立草稿”。
