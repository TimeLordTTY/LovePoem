## 情晓录构建与本地预览

在 `poemapp` 根目录的 PowerShell 中：

```powershell
npm ci
npm run mobile:dev -- --host 127.0.0.1 --port 3002
```

当前产品网页入口由 Vite `mobile/` 构建；静态产物在 `mobile-dist/`：

```powershell
npm run mobile:build
```

Android 调试 APK（Windows）：

```powershell
$env:JAVA_HOME = 'C:\Program Files\Eclipse Adoptium\<实际JDK17目录>'
$env:ANDROID_HOME = Join-Path $env:LOCALAPPDATA 'Android\Sdk'
$env:ANDROID_SDK_ROOT = $env:ANDROID_HOME
npm run android:apk
```

APK 位于 `android/app/build/outputs/apk/debug/app-debug.apk`，当前 `android/app/build.gradle` 标记为 `versionName 1.6`、`versionCode 7`。现有线上测试包：`https://poem.timelordtty.cn/qingxiaolu/qingxiaolu-1.6.apk`。这是 debug 包，换电脑的调试签名通常不同；覆盖安装可能因签名不同失败，卸载会清除 Android WebView 本地数据，务必先导出/同步内容。正式发布需建立稳定的发布签名。

根目录 `npm run dev` / `npm run build` 运行的是较早的 vinext `app/` 原型；现有线上网页不是它。`scripts/start-all.ps1` 和 `scripts/build-all.ps1` 也是原电脑特定的一键流程，执行前检查依赖与路径。

## LovePoem 本地联调

私有仓库：`https://github.com/TimeLordTTY/LovePoem.git`。将它克隆到 `poemapp/integration/LovePoem`。其技术栈是 Vue 3/Vite 与 Spring Boot 3.1.5/Java 17/MySQL，仓库自己的 `README.md`、`database/` 和 `backend/pom.xml` 为初始环境依据。

原电脑脚本约定：MySQL `127.0.0.1:9009`、Java API `http://127.0.0.1:8080/api`、LovePoem 前端 `http://127.0.0.1:3010/`、情晓录原型 `http://127.0.0.1:3002/`。新电脑可自行调整端口与脚本。LovePoem 的数据库初始化脚本只能导入本机新建的测试库，不能导入线上库。

只需测试情晓录与现有线上接口时，可以先不安装本地 MySQL/Java；`mobile/sync.ts` 和 `mobile/WebsitePublish.tsx` 默认连线上 HTTPS 地址。涉及真实内容写入的测试应使用明确的测试项目和草稿。

## 更新线上网页的安全流程

1. 先比较本地 `mobile-dist/index.html` 与线上 `/www/wwwroot/qingxiaolu/frontend/index.html`，确认当前改动确实要上线；检查产品页面及同步功能。
2. 本地 `npm ci`、`npm run mobile:build`，在浏览器测试主要流程。需要 APK 时另跑 `npm run android:apk` 并真机验证。
3. 在服务器为现有 `/www/wwwroot/qingxiaolu/frontend` 做带日期的备份，保留其中用户导入图片和已发布 APK。上传到单独临时目录并核对文件数与哈希。
4. 将构建产物部署到该目录，保持 `qingxiaolu-api`、LovePoem 后端、MySQL 和网站原有数据不变。若改动 Nginx，先备份配置、运行 `nginx -t`，通过后 reload。
5. 用 `curl -I` 检查网页、同步 `/health`、APK 链接；在桌面浏览器和 Android 真机验证登录、编辑、同步和历史显示。发现问题恢复带日期备份。

只更新网页静态页面时，可在本地先打包 `mobile-dist/index.html`、`mobile-dist/assets/`、`mobile-dist/runners/`，再用 `scp` 传到服务器 `/tmp/`。服务器先 `cp -a /www/wwwroot/qingxiaolu/frontend /www/backup/<带日期名称>`，将归档解到单独临时目录并确认 `index.html` 存在，随后把这些静态文件覆盖到 `/www/wwwroot/qingxiaolu/frontend/`。不要删除该目录中的 `imports/` 图片和已供下载的 APK；静态文件更新通常不必重启 Java、同步服务或 Nginx。若部署失败，使用刚创建的带日期备份恢复。打包和复制使用明确路径，避免在服务器根目录执行通配符删除。

更新同步服务需要单独打包 `sync-server/`，在服务器备份 `backend/` 后安装依赖，核对 `/etc/qingxiaolu-sync/qingxiaolu-sync.env` 与数据库 schema，再更新文件并重启 `qingxiaolu-sync.service`。`sync-server/server.mjs` 启动时会运行 `schema.sql` 的建表迁移，绝不可对未知数据库盲目执行。LovePoem Java/JAR 的更新是另一套流程，不因情晓录网页更新而替换。

同步服务的环境变量名称见 `sync-server/server.mjs`：`HOST`、`PORT`、`SYNC_TOKEN`、`SYNC_AUTH_USER`、`DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USER`、`DB_PASSWORD`（用户和密码也可使用对应的 `_BASE64` 变量）。实际值保存在服务器配置文件，不在源码包中。原电脑的 `sync-server/.env` 属本地私密配置，已从交接包排除；新电脑只在需要本地运行同步服务时配置自己的测试值。
