# 情晓录项目思维树适配方案

日期：2026-10-15。本文保留开发前的设计取舍；实际交付范围及验收见《思维树开发与验收-20261015》。设计依据用户提供的《无限探索》分析说明，并核对情晓录当前代码；未独立核验源项目 PR 的现时状态。

## 一、作者实际使用方式

项目内增加「思维树」入口，一个项目允许多张树。作者可从空白树开始整理灵感，也可选择已有文章、人物、章节和事件作为节点。节点负责组织思路，正文和资料继续在原来的编辑器维护。

典型流程：进入项目 → 新建「故事构思」 → 添加自由想法 → 关联人物和章节 → 调整分支、折叠与搜索 → 打开原资料修改 → 返回原树及原节点。第一次进入不自动创建、拆分或重排原资料。

人物关系、世界观和伏笔只是使用示例，不限制树的题材，也不强迫套用模板。

## 二、从参考方案保留与调整的部分

| 事项 | 情晓录的决定与理由 |
| --- | --- |
| 稳定 ID、轻节点引用原资料 | 采用；同名资料不能靠名称关联，改名不丢关系 |
| 直接移植源项目界面 | 不采用；据提供说明，源界面是只读路径列表，缺少编辑画布 |
| 服务器作为唯一权威存储 | 调整为情晓录现有本机优先；不改变离线写作和作者选择同步的规则 |
| 所有资料都是独立实体 | 按实际结构处理；世界观、情节等目前是整段文本，不能虚构条目 ID |
| 父子结构与横向关系 | 分开；第一版交付可编辑层级树，横向关系在后续明确开发后再开放 |
| 自动布局与自由坐标同时保存 | 第一版采用自动布局，拖动用于换父节点或重排；不加入互相矛盾的自由坐标状态 |

## 三、现有代码依据与接入点

- `mobile/ProjectWorkspace.tsx`：`ProjectWorkspaceData`、项目内导航、`patch`、串行 `persist`、版本恢复和文件夹同步。首选从这里增加入口，导图组件独立成文件。
- `mobile/sync.ts`：`queueItem`、本机队列、版本与本地回收站。继续使用现有保存链路。
- `mobile/projectSession.ts`：项目编辑会话、快照指纹及版本基线。沿用整项目并发保护，不另造一套容易互相覆盖的树同步机制。
- `mobile/backup.ts`：项目工作区及完整备份。新增字段需要覆盖备份、恢复、回收站与项目版本回归。
- `sync-server/server.mjs`：已有通用项目 JSON 保存和 `baseRevision` 冲突检查；它不等于已有树结构校验。
- `vite.mobile.config.ts`、`package.json`：当前界面采用 React；Android 使用 Capacitor。网页和 Android 应复用同一模型与组件。

### 真实引用映射

| 作者看到的内容 | 引用身份 | 打开位置 |
| --- | --- | --- |
| 文章、随笔、灵感记录 | 当前项目下的记录 ID；保持原 `itemType` | 已有记录编辑器 |
| 人物 | `characterCards[].id` | 人物资料及对应卡片 |
| 章节／大纲条目 | `chapters[].id` | 大纲中对应章节；不等同于自动生成一篇正文 |
| 故事事件 | `timelineEvents[].id` | 时间轴对应事件 |
| 世界观、情节、概述等整段资料 | 当前项目 ID + 受限字段名 | 对应资料页面 |

第一版仅允许当前项目引用。原对象改名，节点默认跟随；自定义节点别名不改原对象。目标消失时保留节点、别名及说明，显示「引用已失效」。删除节点、树或分支不删除目标对象。

## 四、数据与保存设计

在 `ProjectWorkspaceData` 中新增可选 `mindTrees` 数组。旧项目没有此字段时按空列表显示，不要求重建项目或迁移数据库。树随项目保存、按原有开关同步，冲突粒度仍为整个项目；第一版不承诺逐节点自动合并。

建议模型（待实现）：

```ts
type MindTree = {
  schemaVersion: 1;
  id: string;
  title: string;
  rootNodeId: string;
  nodes: Array<{
    id: string;
    parentId: string | null;
    order: number;
    text: string;
    note: string;
    collapsed: boolean;
    ref?:
      | { kind: "record" | "character" | "chapter" | "event"; id: string }
      | { kind: "projectSection"; section: "world" | "plot" | "characters" | "outline" | "timeline" | "privateNotes" };
  }>;
};
```

项目 ID 由所属项目上下文确定，解析引用时再次校验归属。`text` 是自由文字或引用别名，空别名从目标计算显示名称。根节点 ID 稳定；改树名不强行改用户自定义的根节点文字。

画布平移、缩放及上次选中节点属于设备视图状态，不因缩放产生项目云端版本。折叠状态是整理结构的一部分，随树保存。坐标由层级和顺序计算，不作为第一版业务字段。

保存使用项目现有自动保存和离开前保存；写入成功才显示已保存。失败保留当前编辑并提供重试与导出。输入编辑合并为一个撤销步骤，移动和删除各为独立步骤。撤销／重做仅修改树结构，不回滚关联原文；读取外部版本后清空过时的撤销栈并提示。

删除树或包含子节点的分支时显示名称和受影响数量。除当前会话撤销外，还须先可靠保留可恢复的项目资料版本；保留失败则不执行删除，不能只靠一个随页面消失的内存栈保护内容。

树结构校验至少包括唯一 ID、一个有效根节点、有效父节点、全部节点可从根到达、无父子环路、同级顺序规范化、字段及输入规模限制。未知协议版本不得静默降级后覆盖；失效内容引用与损坏父子结构分开处理。服务端若接收含树的项目，也要验证结构，不能仅依赖客户端。

旧版本客户端及旧备份可能缺少树字段：必须测试读回、合并与恢复行为，避免普通资料保存或旧文件夹读回无提示清掉新树。无法安全兼容时提示冲突并保留当前版本，不能宣称已经天然兼容。

## 五、第一版交互范围

- 多树创建、命名、切换、删除和恢复。
- 自由节点及上述真实引用节点；备注编辑与原资料跳转。
- 新增子节点、同级节点；换父节点、同级排序；禁止移到自身或后代下面。
- 自动布局、展开折叠、画布平移、缩放、适配全图、节点搜索定位。
- 搜索命中折叠分支时展开到目标，保留清楚的当前选择。
- 撤销、重做、自动保存状态及失败处理。
- 桌面键盘操作只在画布焦点内生效，不抢占文字输入；输入法组合期间不提交节点或触发快捷键。
- 手机提供明确的新增、编辑、移动与删除按钮；移动也能通过目标父节点选择完成，不依赖精细拖动。
- 手机单指平移、双指缩放、节点点击与软键盘避让需要单独验收，不能以桌面点击测试代替。
- 画布旁保留可读的层级视图，便于键盘操作、小屏整理和定位复杂分支。

第一版包含独立树 JSON 导入／导出与项目完整备份，导入先校验和预览。原项目恢复保持 ID；复制到其他项目要重新分配树与节点 ID，并明确处理无法映射的引用，不能按同名自动匹配。

横向关系线、图片节点、自由坐标布局、AI 自动生成、多人实时协作和 PNG／SVG／PDF 导出不列为已实现能力。后续按明确需求补充。原有 XMind／OPML 导入不擅自改为导图入口，避免改变现有导入归属。

## 六、组件及绘图实现取舍

建议拆出纯 TypeScript 模型操作、引用解析、布局计算和 React 编辑器；业务数据不依赖某个绘图库的内部序列化格式。

先用一个独立技术样例验证 SVG 连线与可访问 DOM 节点、自动布局和触摸操作能否满足数百节点。若引入外部库，需根据届时官方文档核对 React／Android WebView 兼容性、许可、维护状态和体积，再确定依赖；本方案不声称已完成库选型。

性能测试用实际耗时、输入响应和设备信息报告，不用「无限节点」作容量承诺；深层树处理避免依赖无限递归调用栈。

## 七、实施与验收顺序

1. 模型及保存：树操作、校验、稳定 ID、自动保存、项目版本、完整备份与旧数据兼容。
2. 项目入口及编辑器：图形／层级视图、节点整理、引用解析和返回定位。
3. 手机操作：手势、选择式移动、软键盘、系统返回及原生 JSON 文件保存。
4. 网页／Android 共用数据、离线刷新、双端冲突及文件夹往返。
5. 经定向测试和实际操作后，再分别发布网页、电脑助手和同签名 APK；当前设计稿不表示已上线。

必须核对：快速连建不丢节点；删除恢复不丢子树；父子环路拒绝；原文／资料哈希不因图操作改变；同名项目隔离；引用改名跟随与失效提示；搜索展开；撤销边界；保存失败重试；跨页面冲突；完整备份和独立导入往返；旧数据缺字段；数百节点与长标题；手机触摸和输入法。

最终验收以保存、刷新、恢复后数据一致及原资料不受损为准。原有系统尚未完成的真实 WPS、社交客户端和扩展验收继续保留，不把新思维树设计视为消除了那些边界。
